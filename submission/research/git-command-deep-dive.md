# 02 Git Command Deep-Dive

## 1. Git Squash

### السيناريو:

لما أكون شغال على Feature وعملت كذا commit صغير أثناء الشغل، زي إني أصلحت Bug وبعدها عدلت حاجة تانية وبعدها عملت Fix تاني، في الآخر ممكن أعمل Squash وأجمع الـ commits دي في commit واحد.

### ليه أستخدمه؟

عشان أخلي الـ Git history أنضف وأسهل في القراءة، بدل ما يبقى عندي commits كتير ملهاش أهمية.

**قبل:**

```text
A-B-C

feature:
C → C1-C2-C3-C4
```

**بعد:**

```text
A-B-C

feature:
C → X

X = C1+C2+C3+C4
```

## 2. Git Merge vs Git Rebase

الاتنين بيعملوا حاجة قريبة بس مش نفس الطريقة.

الـ merge بستخدمه لما عايز أدمج فرع جوه التاني وأحافظ على تاريخ الكومِتات زي ما هو (بيعمل كومِت دمج جديد)، وده مفيد في الفروع المشتركة زي main. أما الـ rebase فبستخدمه لما عايز آخد آخر تعديلات من main وأنا لسه شغال في فرعي الخاص، عشان تاريخ الفرع يفضل خط مستقيم من غير كومِتات دمج زيادة، بس بتجنبه لو الفرع ده حد تاني كمان شغال عليه.

### الرسم:

```text
قبل:

main:    A-B-C-F
feature: C-D-E


بعد:

main:    A-B-C-F
feature:       F-D'-E'
```

## 3. Git Help

### السيناريو:

لو قابلني command في Git ومش فاكر بيستخدم إزاي أو عايز أعرف الـ options اللي بيقدمها، أقدر أستخدم git help.

### ليه أستخدمه؟

عشان أرجع للـ documentation الخاصة بالـ command بدل ما أدور في مصادر تانية.

## 4. Git Cherry-Pick

### السيناريو:

لو عندي Bug اتصلح في branch معين، وأنا محتاج نفس الإصلاح في branch تاني، لكن مش عايز أنقل كل التعديلات الموجودة في الـ branch الأول. باستخدم cherry-pick عشان أنقل commit معين لوحده للـ branch اللي أنا شغال عليه.

### الرسم:

```text
main:     A---B---C

feature:  A---B---C---D---E---F
```

```text
git checkout main

git cherry-pick E
```

```text
main:     A---B---C---E'

feature:  A---B---C---D---E---F
```

## 5. Git Clean

### السيناريو:

لو عندي في المشروع ملفات مؤقتة أو ملفات اتعملت أثناء الـ build ومش متتبعة بواسطة Git، وعايز أنضف الـ working directory.

### ليه أستخدمه؟

git clean بيحذف الـ untracked files.

الأفضل الأول أشوف إيه اللي هيتحذف:

```bash
git clean -n
```

وبعد ما أتأكد:

```bash
git clean -f
```

## 6. Git Grep

### السيناريو:

لو شغال على مشروع كبير وعايز أعرف كل الأماكن اللي فيها كلمة معينة، زي TODO أو اسم function معين، بدل ما أفتح كل ملف وأدور بنفسي.

git grep بيساعدني أبحث بسرعة جوه ملفات المشروع عن كلمة أو pattern معين.

### مثال:

```bash
git grep "TODO"
```

---

## 7. Git Blame

### السيناريو:

لو لقيت سطر في الكود فيه مشكلة ومحتاج أعرف مين آخر شخص عدله، عشان أفهم التغيير ده اتعمل ليه أو أرجع للـ commit اللي حصل فيه.

git blame بيوريني مين عمل آخر تعديل لكل سطر في الملف والـ commit المرتبط بالتعديل ده.

### مثال:

```bash
git blame Program.cs
```

---

## 8. Git Bisect

### السيناريو:

لو المشروع كان شغال كويس وبعد شوية ظهر Bug، وأنا مش عارف أنهي commit هو اللي سبب المشكلة، خصوصًا لو كان فيه commits كتير بين النسخة السليمة والنسخة اللي فيها المشكلة.

git bisect بيساعدني ألاقي الـ commit اللي سبب المشكلة باستخدام Binary Search، بدل ما أجرب كل commit واحد واحد.

### الرسم:

```text
Good                              Bad
 ↓                                 ↓

A---B---C---D---E---F---G---H---I

              ↑
        Git Bisect
```

## 9. Git Shortlog

### السيناريو:

لو أنا شغال مع Team وعايز في نهاية فترة معينة أشوف بشكل سريع كل شخص عمل كام commit في المشروع.

git shortlog بيعمل summary للـ commits وبيجمعها حسب الـ author، فبيكون مفيد لمعرفة مساهمات كل شخص.

### مثال:

```bash
git shortlog -s -n
```

### الـ `-s` (summary)

بدل ما يوريك رسالة كل كومِت، بيديك بس **العدد** كام كومِت لكل شخص، من غير تفاصيل. يعني مختصرة أوي.

### الـ `-n` (number)

بترتب النتيجة **من الأكتر مساهمة للأقل**، بدل الترتيب الأبجدي بالاسم.

## 10. Git Prune

### السيناريو:

بستخدمه عشان أنضف الكومِتات والأوبجيكتس اللي بقت مش متوصلة لأي فرع غالبًا بعد ما بمسح فروع قديمة أو بعمل عمليات تنضيف تانية زي rebase كتير، عشان مساحة الـ repo متكبرش من غير داعي.

### مثال:

```bash
git prune
```

وده command لازم أستخدمه بحذر لأنه ممكن يحذف objects مش هقدر أوصل لها بعد كده.

## 11. Git Worktree

### السيناريو:

لو أنا شغال على Feature ولسه مخلصتهاش، وفجأة ظهر Bug مهم في main وعايز أصلحه، مش عايز أعمل stash للتعديلات بتاعتي كل شوية.

### ليه أستخدمه؟

git worktree بيسمحلي أعمل folder تاني لنفس الـ repository وأشتغل فيه على branch مختلف، وفي نفس الوقت أسيب الـ Feature بتاعتي زي ما هي في الـ folder الأساسي.

### مثال:

```bash
git worktree add ../hotfix main
```

## 12. Git Verify-Commit

### السيناريو:

لو المشروع بيستخدم signed commits، وعايز أتأكد إن commit معين فعلًا عليه توقيع صحيح قبل ما أعتمد عليه.

git verify-commit بيخليني أتحقق من الـ signature الموجودة على الـ commit.

الشخص أول حاجة بيعمل مفتاح GPG خاص بيه، ويربطه بحساب الـ git بتاعه. بعدين لما يعمل commit، بيضيف -S:

```bash
git commit -S -m
```

### مثال:

```bash
git verify-commit abc123
```

## 13. Git Filter-Repo

### السيناريو:

لو بالغلط رفعت Password أو API Key في commit قديم، مجرد إني أمسح الملف دلوقتي مش كفاية، لأن البيانات لسه موجودة في الـ Git history.

git filter-repo بيساعدني أعدل تاريخ الـ repository وأشيل الملف أو البيانات الحساسة من الـ history بالكامل.

### مثال:

```bash
git filter-repo --path secret.txt --invert-paths
```

وده أمر قوي ولازم أستخدمه بحذر، خصوصًا لو الـ repository متشارك مع ناس تانية، لأنه بيغير الـ history.
